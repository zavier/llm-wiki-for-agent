# 上下文文件证据记分卡(Context Files: Evidence)

把目前手上的五份一手材料并排看:**它们不矛盾,它们在测不同的东西**。这一页的作用是防止拿一句"AGENTS.md 有害/有用"到处套。

## 一句话现状

**写对了能省时间(效率),但不能提高成功率(质量);写得不对会主动改坏能跑的代码(时效权威);而大多数文件写的正是最容易腐烂、也最没用的那部分内容。**

## 记分卡

## 三处"矛盾"及其解释

**① 成本 +20% vs token -16.6%(ETH vs Lulla)**
两者基线都是"无文件",所以差异来自**文件来源**与**任务形态**:
- ETH 测的是**官方 `/init` 生成的**文件,在**冷门基准仓库**的 issue 任务上——那类仓库缺少文档,生成物把冗余塞进上下文;
- Lulla 测的是**开发者手写的根文件**,在**≤100 行改动的真实 PR** 上——这类任务高度依赖"项目约定/结构"的**探索成本**,文件把它省掉了;
- 指标也不同:ETH 数**步数与美元**(生成物触发额外测试与探索),Lulla 数**token 与墙钟**。
→ 一个可检验的解读:**文件省的是导航,贵的是要求**(见 [[documentation-redundancy]])。目前这只是假设,两篇都没做联合测量(成功率 × token 同时测)。标注:genuine conflict,未解。

**② 文件"在被主动维护" vs "73.8% 一次不改"**
[[2025-11-17-agent-readmes]] 的语料是**活跃公开 OSS**(67% 的 CLAUDE.md 多次修改、中位间隔约 1 天);[[2026-10-22-stale-instruction-files]] 引的是**441 个公司仓库**(73.8% 只提交一次)。人群不同,不能对撞。真实分布很可能是双峰:**活跃项目持续修,内部/一次性项目写完就凉**。目前无同人群对照。

**③ "指令被遵循" vs "遵守率 0–78%"**
不冲突,是**分辨率**差异:ETH 看的是**工具提及的采纳**(提到 uv → 每实例 1.6 次;未提 <0.01),近似二元;Tsuchida 看的是**逐函数、必须全部命中的精确规则**,而且发现了措辞与模型的强依赖。另有 McMillan 的四面析因(长度/位置/结构/冲突策略)**都不显著改变遵守率** —— 意味着"文件太长所以被忽略"这个流行说法,缺证据。

## 分维度当前结论

- **成功率**:不普遍提升(ETH v3 结论已从 v1 的"LLM 生成有害、人写 +4%"软化为"两类都不普遍提升";人写的优势是相对生成物的 **+7pp**,而非绝对收益)
- **效率**:手写根文件在小 PR 上明显更省(单研究、单模型、无质量对照;证据等级:低-中)
- **遵守**:措辞与 harness/模型决定一切,范围 0–78%;条件式要避免;证据等级:中(两研究 + 一析因,但单策略/单文本)
- **内容**:功能压倒一切,安全/性能各约 1/7 的文件提到(强)
- **时效**:陈旧文件不仅误导而且**覆盖正确信息**、导致**改坏能跑的代码**;修法便宜(一句话);证据等级:高(单研究但效应量极大 + 机制清楚)

## 可执行清单

1. **不要 `/init` 直接入库**。要写就**人写**,并只写代码里看不出的东西(必须用 uv/make 目标、非默认约定、外部服务入口、红线)
2. **不写目录概览与"当前实现"描述**:既不缩短寻址(ETH),又最容易腐烂(E 细则)
3. **用直接指令,不用条件句**;"如果…就…"的遵守率最低;不要指望同一份文件在多个模型上都是最优写法
4. **用户级文件加一句元规则**:"文档与既有代码冲突时以代码为准,并在最终回复里报告冲突"(见 [[instruction-hierarchy]])
5. **需要确定性的,别用散文**:该拦的用 hook/权限/CI(见 [[three-tier-boundaries]]、[[governance-as-code]]);文件负责"偏好",机制负责"边界"
6. **文件纳入 PR 评审**:改动让文件过时的,修正作为该 PR 的一部分;把代理报告的冲突清单接成修文件 PR
7. **别把"文件存在"当治理证据**;要评就三条轴一起:成功率、成本、遵守率(见 [[agent-evals]])

## 开放问题

- **同人群对照**:公开活跃 vs 公司内部仓库的维护率与腐烂速度
- **联合测量**:同一批任务上同时报"成功率 + token + 时长" —— 目前没有任何一篇同时给(Lulla 缺质量,ETH 缺分钟级时长)
- **外部效度**:全部实验都在 Python(ETH 自认参数知识可能掩盖效应);冷门语言/私有栈上结论可能翻向
- **优先级句的边界**:项目级文件也有效吗?与"代码本身才是错的"场景(重构遗留)如何区分权威?
- **开放权重天花板**:qwen-code ≤20% 是模型问题还是 ACF 注入方式问题 —— 若是后者,换 harness 可解
- **未覆盖的安全面**:指令文件被投毒/第三方仓库自带恶意 AGENTS.md 的攻防(已有 CSA 研究笔记,尚未入库)
