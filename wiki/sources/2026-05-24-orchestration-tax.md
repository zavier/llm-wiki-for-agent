# The Orchestration Tax (2026-05-24)

- 原文: `raw/The Orchestration Tax.md`
- 类型: 技术博客([[addy-osmani]],发布于 **2026-05-24**,frontmatter 已标注)
- 备注: 本 wiki 第三十一篇源文档;**\"编排税\"术语的正式定名**(Google I/O panel 上 Richard Seroter 命名,Osmani 展开);短小但定义了多代理时代的核心经济概念——启动代理便宜、闭环评审贵,\"你\"是唯一串行处理器;"不是纪律问题,是架构问题"

## 摘要

开代理容易,跑多个代理不等于有多个你——所有判断与合并仍然路由经过**一个串行处理器:你**。编排税 = 忘记这个事实的代价;唯一真修复 = **像架构并发系统一样架构自己的注意力**。核心类比:你是你代理们的 GIL(一次只有一个能拿到锁);Amdahl 定律精确化——串行部分(判断)占比决定加速上限,开 8 个代理只让喂给瓶颈的队列更深;\"优化非瓶颈部分不增加吞吐\"——代理加的是从不是约束的部分,约束是评审步。硬拼无效:税照付,表现为浅层评审或 [[cognitive-surrender|认知投降]]。五条实践:按评审率缩放舰队(回压)、分类工作(隔离 vs 判断即工作——别并行第二堆)、批量评审(减少冷 reload)、只在判断上花锁(机器可自证的 80% 别耗人)、保护串行时间(最高杠杆 = 停止编排,握着锁想一个问题)。不付税 = 同时累积技术债+认知债(Storey 债务框架),且失败模式对你不可见(忙 ≠ 生产力,从内部看一模一样)。

## 关键主张

**不对称**:启动代理 = 一个按键/一句 prompt(便宜);闭环 = 检查正确性 + 调和与其他代理的触碰 = 你(昂贵);\"有一个你,只有一个\";把代理开发看成并发系统后,人是组件——**慢的串行组件**

**GIL 类比**:Python GIL——线程随便开,一次只有一个执行字节码,都要抢锁;\"你就是你 AI 代理们的 GIL\"——它们可同时跑,但需要真理解架构或解合并冲突的工作必须拿到锁,锁只有一把,你握着

**Amdahl 精确化**:加速上限 = 1/(1 - 可并行比例);代理开发里的串行分数 = **判断**(judgement);8 个代理不加速你的判断时间,只加深喂给它的队列;\"优化非瓶颈不增加吞吐,只让未完成工作在瓶颈前堆得更高\"——代理优化了从来不是约束的部分,约束是评审步,系统吞吐 = 评审步吞吐;**编排税 = 代理产出与你实际能合并之间的结构性缺口** = \"把单线程资源放进并发系统的负责人位置\"

**疲劳的结构成因**:串行处理器 100% 无 slack;每次 check-in 付 **context switch 成本**(flush 脑 + 冷 reload;CPU 微秒级且架构师仍回避,你花分钟且永远无法完美 reload);5 个代理 = 5 次冷 reload + 后台脑进程持续焦虑\"该检查哪个\"(上月文 *Your parallel Agent limit* 写过这种 ambient anxiety)

**硬拼无效**:税无论如何会付——要么刻意付,要么让它\"悄悄毁掉你对系统的理解\"(表现为浅层评审/认知投降:接受代理代码因为形成观点要付的注意力没了)

**五条实践(架构你的注意力)**:
1. **按评审率缩放舰队,不按 UI**:回压(backpressure)——agent 数是生产者,评审率是消费者,生产者应匹配消费者;正确并行数 = 你能真正评审好的数量,对多数人是**个位低位数**;\"AI 工具乐意让你开 20 个,那只是 UI 功能\"
2. **分类工作(两堆)**:隔离工作(委托云端后台代理,异步,最终门槛才需要你)vs 复杂任务(判断即工作:怪 bug/架构设计);**大错 = 并行化第二堆**——多个复杂任务不扩展产出,只是抖动锁,一切更糟
3. **批量评审**:一次坐着审 4 个代理比逐个冷切换便宜得多;给代理长绳,让工作堆一点再批量处理
4. **只在判断上花锁**:机器能自证的事别浪费大脑——让代理写通过的测试/生成截图,证明无聊的 80%,你只花稀缺注意力在真需要人的 20%
5. **保护串行时间**:瓶颈需要最好的时段,不是 check-in 之间的边角料;有时最高杠杆 = 完全停止编排、合上笔记本、握着锁想一个单一问题;\"**编排不是真正的工作,是工作周围的 overhead**\"

**忙 vs 生产力**:失败模式**对你不可见**——20 个代理跑 = 巨大生产力感,dashboard 满,但感觉与\"往 main 运好代码\"脱钩,从内部看一模一样;Ciera Jaspan 引 Margaret-Anne Storey 的债务工作(技术债+认知债,她 2026-02-09 博客):**编排税不付 = 同时累积两种债**——合并没好好读的(技术债)+ 心智模型过期(认知债);今天 dashboard 不显示,生产爆了才发现\"完全不知道它怎么工作了\"

**收尾**:\"开代理不是技能,任何人都能跑 20;真技能 = 围绕唯一不能克隆/并行化的串行资源(你的注意力)设计系统\";Aja Hammerly:架构是紧急技能(什么属于一个代理内、什么对它太多);人 = 系统组件,注意力有已知的低串行吞吐——系统要么尊重这个数,要么绕开它(悄悄降低你的标准)
