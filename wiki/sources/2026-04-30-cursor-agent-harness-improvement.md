# 持续改进我们的智能体框架 (2026-04-30)

- 原文: `raw/持续改进我们的智能体框架.md`
- 类型: Cursor(Anysphere)官方工程博客(**作者 Stefan Heule**;**发布于 2026-04-30**,frontmatter 已标注;中文版)
- 备注: 本 wiki 第十八篇源文档;**首个 Cursor 阵营**(第四家公司:Anthropic/OpenAI/Osmani/独立/Cursor);主题:智能体框架(harnass)的持续改进方法论——评测体系、回归追踪、按模型定制

## 摘要

Cursor 把智能体框架当作任何有野心的软件产品来构建:愿景驱动 → 假设 → 实验验证 → 按评估与真实用量信号持续迭代。核心内容:上下文工程从"护栏+静态上下文"演进到"动态上下文";双层评测(离线 CursorBench + 在线 A/B)与两个真实质量指标(**Keep Rate 保留率**、语义满意度);按模型定制框架(OpenAI patch 格式 vs Anthropic str_replace、提供商定制提示);工具错误分类与异常检测告警;上下文焦虑的第三次独立观察(缓解方式为提示调优);对话中途换模型的挑战;多智能体编排是框架问题。

## 关键主张

- **框架改进 = 产品工程**:愿景 → 假设 → 实验 → 评估+真实用量信号;需要合适的在线/离线观测机制;拿到新模型 Early Access 时花数周围绕模型优势与怪癖定制框架,"同一个模型在我们专门调优过的框架中明显更快更聪明更高效";跃迁式改进少见,**更多是执着地叠加小优化**
- **上下文演进**(对照 [[context-engineering]]):2024 末(编程智能体初代)模型自选上下文能力弱 → 大量护栏:每次编辑后喂 lint/类型错误、行数读太少就改写文件读取请求、限制单轮工具调用数;静态上下文(文件夹布局、查询语义匹配的代码片段、附件压缩版);**如今这些做法大多已淡出**——保留少量静态上下文(OS/git 状态/当前与最近文件),减少护栏、增加**动态上下文**(智能体工作中按需拉取;过往对话/活跃终端会话/工具均可由模型决定何时纳入)
- **双层评测**:
  - 离线:自建评估套件 + 公开基准 **CursorBench**(快速标准化、跨时间对比);但基准只能近似真实使用
  - 在线 A/B:两个以上框架变体真机对照;直接指标(延迟/token 效率/工具调用数/缓存命中率)只能看趋势
  - **Keep Rate(保留率)**:智能体提出的代码变更在固定时间间隔后仍保留在用户代码库的比例——用户手动调整或继续迭代修复 = 初始响应质量低的信号
  - **语义满意度**:用 LLM 读用户对智能体初始输出的回应判断满意与否——用户继续下一个功能 = 完成强信号;粘贴堆栈跟踪 = 未完成的可靠信号
  - 反例:更贵的模型做上下文摘要,质量改善微乎其微,不值得成本(搁置)
- **回归追踪**:工具调用是缺陷率最高的界面;错误留在上下文浪费 token 并致"上下文腐坏"(累积错误降低后续决策质量,见 [[context-rot]]);未知错误一律按框架缺陷处理;**预期错误按成因分类**(InvalidArguments/UnexpectedEnvironment = 模型出错与上下文矛盾;ProviderError = 提供方服务中断;UserAborted/Timeout);告警:未知错误率超阈值即触发;预期错误用**异常检测**(显著高于基线,按每个工具每个模型分别算基线——不同模型工具出错率不同);每周自动化运行(带专门技能教模型搜日志、找新增/激增问题、在 Linear 建带调查信息的工单);云端智能体推动修复;集中冲刺把意外工具错误**降低一个数量级**,所有工具可靠性 ≥99%,很多 99.9%
- **按模型定制框架**:所有抽象不依赖具体模型但可深度定制——**OpenAI 模型训练用 patch 格式编辑文件,Anthropic 模型习惯字符串替换;给不熟悉的格式会额外消耗 reasoning token 并产生更多错误**(配置训练时所用的工具格式);定制提示按提供商与版本(OpenAI 偏字面精确,Claude 偏直觉、容忍不精确指令);Early Access 调优循环(从最接近的现有模型框架起步 → 离线评估 → 团队成员试用反馈 → 迭代到有信心发布);**上下文焦虑第三次独立观察**:某模型在窗口将满时开始拒绝执行任务、犹豫地称"任务看起来太大了"——通过调整提示成功减轻
- **对话中途切换模型**:自动切框架(该模型定制的提示与工具);但模型要把工具应用到**别的模型生成的对话历史上**(不符合训练分布)→ 自定义指令告知"中途接管",并引导避免调用不属于自身工具集的工具;缓存是提供商/模型特定的 → 切换导致缓存未命中(首轮更慢更贵);尝试切换时总结对话缓解,但复杂任务摘要会丢细节;建议除非有明确理由保持同模型;替代方案 = **子智能体**(全新上下文窗口),已支持指定模型运行子智能体
- **未来**:AI 辅助软件工程走向多智能体模式——系统学会在专业化智能体间委派(规划/快速编辑/调试);**调度与整合是框架问题,不在任何单个智能体身上**;框架工程只会更重要
