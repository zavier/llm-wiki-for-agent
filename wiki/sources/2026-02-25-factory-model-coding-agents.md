# The Factory Model: How Coding Agents Changed Software Engineering (2026-02-25)

- 原文: `raw/The Factory Model_ How Coding Agents Changed Software Engineering.md`
- 类型: 技术博客([[addy-osmani|Addy Osmani]],addyosmani.com;**发布于 2026-02-25**,frontmatter 已标注)
- 备注: 本 wiki 第十三篇源文档;Osmani 的第四篇源;**行业范式级论述**(非实操指南)——软件第三纪元、"建工厂而非写代码"、验证是未解问题;与前三篇(实操/学科)形成从"怎么干"到"这意味着什么"的完整层次

## 摘要

软件工程的重心发生了阶跃变化:从"写代码"到"编排写代码的系统"。作者提出工厂心智模型——你不再只是写代码,而是在**建造生产你软件的工厂**(代理舰队:每个代理有任务、工具带、上下文、反馈回路)。核心张力:写代码已剧变,软件工程的本质没变——差距所在正是故事所在。结论:spec 是杠杆、验证是瓶颈、TDD 近乎强制、人的判断力上移到栈顶。

## 关键主张

- **抽象之弧与软件第三纪元**(Grady Booch 框架,经 Cursor 的 Michael Truell 思考引伸):bits → 指令 → 函数 → 对象 → 服务 → 分布式系统;现在:从写代码到**编排写代码的系统**;开发者工作从"写指令"变为"定义意图"
- **AI 编码工具三代**:①加速自动补全(工作流不变,你开工具助);②同步代理(自然语言描述 → 生成 → 你审改;代理是协作者,你持上下文);③**自主代理**(spec 进,30 分钟到数天自己跑:建环境、装依赖、写测试、撞失败、上网研究、修复、实现、再测、部署、产出可审工件;你定义结果 + 审结果)——群体代理(swarms)与自改进代理由此入场
- **工厂心智模型**:代理舰队并行——一人处理后端重构、另一人实现功能、另一人写集成测试、另一人更新文档;你审输出、给反馈、改 spec、再部署。工厂属性直接映射:质量控制、流程文档、输入必须精确否则输出错、**环境不可靠工厂就停摆**;在激进采用的组织里,**合并 PR 的相当部分已来自云端自主运行的代理**(生产现实)
- **入职平行**:代理工作环 ≈ 新工程师入职——给 spec → 拆子任务 → 探索代码库 → 卡住时搜 commit 历史/git blame → 经 Slack 升级给人 → 迭代到验收标准;含义:**Slack/email 正在成为人-代理接口**;git 历史进化成代理导航的知识图谱;文档成为自主执行的训练材料;**投资测试**:仅凭文档 + commit 历史,一个新工程师能理解代码为何如此结构吗?不能 → 代理在那里也会挣扎
- **Spec 是杠杆**:20-50 个代理并行时,平庸与优秀输出的差距几乎全在 spec 质量——**模糊想法会乘法式放大**(含糊需求在几十个并行运行里各自往不同方向偏一点;糟糕的架构决策传播到整个舰队);"spec 不再是一个 prompt,spec 是产品思维的外显";强工程师从这些工具获得更多而非更少杠杆(机械打字被自动化,认知工作被放大)
- **没变的东西**:清晰需求(代理无法澄清从未给它的需求,会用假设填补,假设会复合);强抽象(干净架构更有价值——代理放大所在系统的属性);可靠测试;谨慎权衡(代理优化既定目标,不会平衡竞争性关切、预判二阶效应、或指出"技术上正确但产品上错误");人类监督(自信的错误;输出质量高到能过随意审查 → **你的审查技能门槛提高而非降低**)
- **测试比以往更重要**:红/绿 TDD 在代理工作流中近乎强制——**"优化通过测试的代理会找到通过测试的办法;测试写于实现之后,测的往往是实现恰好做的事,而非它应该做的事"**;测试优先套件是确保自主输出正确、保护既有功能的最有效杠杆;\"告诉代理用 red/green TDD 是任务开始时最高杠杆的指令之一\"
- **未解的问题是验证,不是生成**:生成不再是瓶颈。难的是置信地知道输出是否正确:改动前通过的测试不保证抓到回归;代理会写技术上有效但漏掉关键用例的测试;UI 验证脆弱(视觉/行为回归漏网);上下文窗口限制(大型代码库中代理可能漏掉窗口外约束);**环境抖动从个人烦扰变成系统性阻塞**(40 个代理同时撞同一个 flaky 测试,工厂停摆);需要的基础设施:更好的自动回归检测、超出 diff 行的工件级验证、可靠快速的环供应、扛得住并行负载的护栏——都是未解的投资领域;**在验证追上生成之前,人工审查不是可选开销,是安全系统**
- **高杠杆工程师的新形状**(六项能力):系统思维、问题分解、架构判断、spec 清晰度、**输出评估品味**(认出"看起来对但不对";不可自动化)、编排技能(重定向 vs 重新派任务);都不是新技能,但相对重要性变了
- **宏观数据**(经 nichochar 图表二手引述,待核):新网站创建 +40% YoY、新 iOS 应用 +50%、GitHub 代码推送 +35%(美国)——2024 底前多年持平,之后曲棍球杆;软件创建门槛真实下降,"更多数量≠更好质量"需留意
