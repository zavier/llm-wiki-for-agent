# Comprehension Debt - the hidden cost of AI generated code (2026-03-14)

- 原文: `raw/Comprehension Debt - the hidden cost of AI generated code..md`
- 类型: 技术博客([[addy-osmani|Addy Osmani]],addyosmani.com;**发布于 2026-03-14**,frontmatter 已标注)
- 备注: 本 wiki 第十五篇源文档;Osmani 的第六篇源(时间线:01-07 评审 → 01-13 spec → 02-25 factory → 03-14 本篇 → 04-19 harness);主题:AI 生成代码对人类理解力的隐性成本——对"验证/评审"路线的关键对冲

## 摘要

理解力债务(comprehension debt/cognitive debt):系统里的代码量与人真正理解的部分之间**不断扩大的差距**。与技术债不同,它不通过摩擦自我宣告,而是制造虚假信心——代码库看着干净、测试全绿,清算时刻却悄悄到来。AI 生成速度远超人类评估速度,评审从"质量门"变成"吞吐问题";测试与 spec 都是必要但非充分;唯一稀缺资源变成"真正理解系统的人"。

## 关键主张

- **定义与机制**:理解力债务 = 代码存在量 vs 任何人真正理解量的差距;技术债是清醒的权衡(知道捷径在哪、可排期偿还),理解力债**隐形累积**——是几百次"代码看着没问题、测试通过、队列里还有下一个 PR"的审查的聚合;"代码便宜了,理解没有变便宜可跳"
- **案例**(Margaret-Anne Storey 的学生团队):第七周起无法不弄坏别处而做出简单修改——不是代码乱,是**没人能解释设计决策为何做出、各部分如何协同**;"系统的理论蒸发了"
- **Anthropic RCT 研究**《How AI Impacts Skill Formation》(arXiv 2601.20245,待核):52 名工程师学新库;AI 辅助组完成时间与对照组相近,但**后续理解力测验低 17%(50% vs 67%)**,调试能力降幅最大,概念理解与代码阅读也有显著下降;**被动委派("make it work")对技能发展的损害远大于主动提问式使用**
- **速度不对称**:当代码贵时,资深能比初级写得快;AI 翻转了它——**初级生成代码可以快过资深批判性审计**;过去让评审有意义的限速因素被移除;"表面正确不是系统正确"——语法干净、格式良好正是历史上触发合并信心的信号
- **测试不是完整答案**:覆盖全部可观察行为的测试套件在很多情况下比被测代码更复杂;无法推理的复杂度不提供安全;**"你无法为没想到要指定的行为写测试"**(没人会写"拖拽项不应变成全透明");具体失败模式:**AI 改变实现行为并更新几百条测试去匹配时,问题从"代码对吗"变成"那些测试改动都必要吗,覆盖够不够抓到我没在想的东西?"——测试答不了,只有理解能**;数据(二手):委派式使用理解力 <40%,概念询问式 >65%
- **Spec 也不是完整答案**:spec→代码涉及海量隐式决定(边界/数据结构/错误处理/性能权衡/交互模式),两个工程师实现同一 spec 会产生许多可观察行为差异;**详细到能完全描述程序的 spec ≈ 非可执行语言的程序本身**——组织成本可能超过收益,且仍未审实际产物;通常不存在"正确的 spec",需求在建中浮现
- **向历史学习**:成本(降)/速度(升)/人际管理开销(≈0)变了,**"需要深系统上下文的人维持对代码库的实际理解"没变**;AI 量越大,真正理解系统的人越有价值——能看出 diff 里哪些行为承重、记得八个月前决策为何做、分辨安全重构与悄悄移动用户依赖的重构;**理解力成为整个系统依赖的稀缺资源**
- **测量缺口**:velocity/DORA/PR 数/覆盖率全绿,而没有任何测量工件捕获理解力维度;"激励结构对它所测量的正确优化,而它所测量的已不再捕获重要的东西";**"被评审的代码 = 被理解的代码"这一组织假设不再成立**——工程师批准了没完全理解的代码,责任被悄悄分发
- **监管地平线**:AI 代码进入医疗/金融/政府服务后,"AI 写的、我们没完全审"在事后报告里站不住脚;现在建立理解力纪律的团队会在清算到来时占优
- **要求**:先写清变更该做什么;把验证当结构性约束而非事后;维持系统级心智模型以在**架构尺度**而非逐行尺度抓 AI 错误;诚实区分"测试过了"与"我理解它做了什么、为何这么做";"你迟早要为理解买单,债务以复利增长"
